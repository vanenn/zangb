# 系统与数值

## 武器和阵容

八种基础武器由近战/远程、单体/群体、单次/持续三条轴组合而成。三名开局角色分别使用重型扳手、警棍横扫和自制燃烧瓶；另有消防员、电锯，环卫工、旋转清障刷，猎人、重弩，化工人员、酸液喷枪，拆除工、破拆药包五组可招募幸存者。

武器配置在 data/weapons.json，起始职业与可招募幸存者分别配置在 data/classes.json、data/survivors.json。每组幸存者攻击都由队形中的对应成员自动执行。同类幸存者每两人提升一档协同，最多三档。

## 构筑和战斗

改装数据在 data/mods.json，核心装备在 data/equipment.json。当前共有22项一次性改装：八种武器各两项，另有六项通用改装；核心装备共12件，全队共用四个装备槽。装备候选按现有武器与队伍标签筛选。

run_state.gd 管理局内状态、候选、存档检查与第三版局内存档迁移。build_runtime.gd 处理命中、击杀、拾取、治疗、救援、过热和全队冷却；weapons_runtime.gd 执行攻击和持续效果，scavenge.gd 处理搜刮。地图、队形、招募商店与局外进度由独立模块管理。

近战和远程攻击均受地图遮挡规则约束；投掷攻击能越过低掩体。酸液附着于单体并每半秒结算伤害；火瓶留下区域持续灼烧；旋转清障刷以短间隔重复命中范围内目标。破拆药包在落点进行一次范围伤害。

追加攻击带有追加标记，不能递归触发其他追加攻击。普通敌人的击退受限，首领更难被控制。随机奖励使用独立随机状态，保存的候选在读档后保持一致。

## 存档

局内快照版本为4，接受第三版版本3快照并将已移除的职业、武器与升级牌映射到新阵容；无法映射的旧牌会过滤。局外进度文件维持原有 schema 版本，保留战绩与设置。

初始化时的历史清理仅处理存档根目录中明确列出的 run、progress、settings 文件名及其已知后缀，不递归删除目录。清理完成后写入 schema 标记；后续初始化不会再次清理。

## 美术与验证边界

攻击反馈沿用项目已有的透明序列帧和本地合成音效。当前重构通过攻击范围、命中节奏、区域效果、色彩和反馈类型区分武器；尚未为新武器专门绘制完整动作图集。

docs/VERIFICATION.md 中的自动化与流程结果属于八类武器重构之前的第三版基线，不能视为当前体系通过验证。当前改动尚需补充自动化规则检查、战役模拟和真人试玩。
